# 企业工单与审批系统上线部署说明

## 当前结论

项目已经具备部署为内部生产系统的基础：后端可以打包为 jar，前端可以构建为静态文件，Nginx 负责统一域名、静态文件和 `/api` 反向代理，MySQL、Redis 和附件目录作为持久化服务。

公网长期使用前必须准备域名、HTTPS 证书、服务器防火墙规则、数据库备份和附件备份。没有这些条件时，只能算本机演示或局域网试用。

## 1. 构建

后端在 `enterprise-work-order` 目录执行：

```powershell
mvn clean package -DskipTests
```

产物是 `target/enterprise-work-order-0.0.1-SNAPSHOT.jar`。

前端在 `enterprise-work-order-web` 目录执行：

```powershell
npm ci
npm run build
```

把生成的 `dist` 目录复制到服务器，例如 `/srv/enterprise-work-order/web`。

## 2. 数据库与 Redis

生产环境不要使用 MySQL `root`。创建独立数据库账号，并执行项目 `sql/schema.sql` 及尚未执行的迁移脚本。Redis 需要监听内网或本机地址，并配置密码；不要把 Redis 6379 直接暴露到公网。

附件目录必须放在不会随发布包删除的位置，并纳入备份。数据库备份和附件备份要能分别恢复，否则数据库中的附件记录可能找不到对应文件。

## 3. 注入配置并启动后端

复制 `production.env.example`，把其中的占位值换成真实配置。启动前设置 `SPRING_PROFILES_ACTIVE=prod`，并注入该文件中的变量。Windows PowerShell 示例：

```powershell
$env:SPRING_PROFILES_ACTIVE = "prod"
$env:DB_PASSWORD = "真实数据库密码"
$env:JWT_SECRET = "至少32字节的随机字符串"
$env:CORS_ALLOWED_ORIGINS = "https://你的域名"
java -jar target/enterprise-work-order-0.0.1-SNAPSHOT.jar
```

缺少 `DB_PASSWORD`、`JWT_SECRET` 或 `CORS_ALLOWED_ORIGINS` 时，生产配置会故意启动失败，避免带着默认凭据上线。Agent 的 `LLM_API_KEY` 可以留空，留空只会关闭智能助手，不影响普通工单功能。

## 4. Nginx 与 HTTPS

将 `nginx.conf.example` 复制到 Nginx 配置目录，修改域名和前端目录。先完成 HTTP 访问验证，再申请证书并把 HTTP 重定向到 HTTPS。浏览器只访问 Nginx 的 443 端口，不直接访问 8081、6379 或 MySQL 端口。

验证地址：

```text
https://你的域名/
https://你的域名/actuator/health
```

生产模式会关闭 Swagger，`/swagger-ui.html` 不应作为公开接口使用。

## 5. 上线验收

用真实测试账号依次验证：登录、创建草稿、上传和下载附件、提交、多级审批、驳回后修改重提、通知、导出 Excel、管理员配置、Redis 不可用时的回退行为。确认附件目录可写、重启后附件仍能下载、数据库和附件备份均可恢复。

当前本机的 IDEA 开发启动方式不变；正式运行必须使用 `prod` 配置，并由进程管理器或系统服务负责自动重启和日志保留。
